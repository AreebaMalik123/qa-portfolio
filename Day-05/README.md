Overview
Day 5 focused on understanding the bug life cycle, severity vs priority, and effective bug reporting. I also started Weekly Task 1, which involved exploratory testing of the SauceDemo website and comparing the behavior of different user accounts.
Topics Covered
1. Bug Life Cycle
Learned about the different stages of the bug life cycle:
- New: A newly identified bug reported by QA.
- Assigned: The bug is assigned to a developer.
- Open: The developer reviews and starts working on the bug.
- Fixed: The developer fixes the reported issue.
- Retest: QA tests the issue again after the fix.
- Closed: The issue is verified and successfully resolved.
- Reopened: The bug still exists after retesting.
- Rejected: The reported issue is considered invalid.
- Duplicate: The same issue has already been reported.
- Deferred: The bug is postponed for a future release.
2. Severity vs Priority
Learned the difference between severity and priority:
- Severity: Measures how seriously a bug affects the application.
- Priority: Determines how urgently a bug needs to be fixed.
Also learned about different combinations of severity and priority, including:
- High Severity / High Priority
- High Severity / Low Priority
- Low Severity / High Priority
- Low Severity / Low Priority
3. Good Bug Reporting
Learned the essential elements of an effective bug report:
- Clear Bug Title
- One Bug Per Report
- Numbered Steps to Reproduce
- Expected Result
- Actual Result
- Device and Operating System
- Application Build
- Screenshot or Evidence
4. Jira Basics
Learned the basic concepts of Jira:
- Issue Types
- Issue Fields
- Issue Statuses
- Comments
- Attachments
- Filters
Practice Task – SauceDemo
Started Weekly Task 1: SauceDemo Exploration Report.

The task focuses on exploring the application and comparing the behavior of different user accounts.
1. Feature Map
Identified the main application features:
- Login and Authentication
- Product Listing
- Product Sorting
- Product Details
- Add to Cart
- Shopping Cart
- Checkout
- Order Overview
- Side Menu
- Logout
2. Exploratory Testing Charters
Prepared three exploratory testing areas:
1. Login Functionality: Exploring valid and invalid credentials, error messages, and login behavior.
2. Shopping Cart: Exploring adding products, removing products, and cart functionality.
3. Checkout Process: Exploring customer information, field validation, order overview, and order completion.
3. Comparative Testing
Explored the behavior of different SauceDemo user accounts:
- standard_user
- problem_user
- error_user
- visual_user
Focused on identifying functional and UI-related differences and documenting issues with screenshots.
4. Highest-Risk Area
Checkout Process

The checkout process appears to be one of the highest-risk areas because it is a critical part of the shopping journey. Issues such as incorrect input field behavior, validation problems, and failure to complete an order can negatively affect the user experience. Therefore, checkout functionality requires careful testing to ensure users can successfully complete their purchases.
